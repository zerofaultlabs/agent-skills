# Validation protocol

Keep test answers outside the production skill.

## Blind generation

1. Create a source packet containing only the sermon transcript and ordinary user request.
2. Exclude historical posts, comparison notes, expected selections, performance data, and prior test results.
3. Generate the complete recommendation and copy using the production workflow.
4. Save the output with the input identifiers and a timestamp or checksum before opening any answer key.

## Reveal and compare

After sealing the output, compare it with the historical post on:

- central biblical truth;
- human problem and audience relevance;
- Christ, Scripture, or hope movement;
- selected sermon moment and timestamp range;
- carousel versus reel role;
- hook structure;
- caption voice and CTA;
- important omissions;
- unsupported additions.

First verify that a corresponding historical sermon post or reel was actually published. Treat “no content was created” as a scheduling fact, not as a failed editorial match. A weekend photo recap or caption that mentions the sermon is not interchangeable with a dedicated Tuesday carousel or Thursday reel; record the actual format and relationship precisely.

Classify each difference as:

- equivalent creative variation;
- useful alternate;
- meaningful mismatch;
- missing evidence or unresolved human preference.

Change the production skill only for a transferable failure supported by more than wording preference. Keep case-specific answers in the external test record, not in this folder.

## Human review handoff

For each review item, include the direct Instagram URL, sermon URL, match confidence, published choice, proposed alternative, and the specific decision requested. If the post may be unrelated to the sermon, ask the reviewer to confirm the relationship before asking which creative treatment is stronger. Record an unconfirmed relationship as missing evidence, even when the alternative receives a positive reaction.
